## 1. 개요

NFS(Network File System)는 네트워크 너머의 파일과 디렉터리를 로컬 경로처럼 사용할 수 있게 하는 분산 파일시스템 프로토콜이다. 서버는 공유할 디렉터리를 제공하고, 클라이언트는 이를 자신의 디렉터리 트리에 마운트한다.[^1]

NFS는 원격 디스크의 블록을 그대로 빌려주는 기술이 아니다. 클라이언트가 “이 파일을 열어 이 위치부터 읽어 달라”고 요청하면 NFS 서버가 자신의 파일시스템에서 해당 작업을 수행한다.

## 2. 마운트 이후의 동작

```mermaid
flowchart LR
    A[애플리케이션<br/>read·write] --> V[클라이언트 VFS]
    V --> C[NFS 클라이언트]
    C -- 네트워크 파일 요청 --> S[NFS 서버]
    S --> F[서버 파일시스템]
    F --> B[서버 블록 계층]
    B --> D[(HDD·SSD·스토리지)]
```

애플리케이션은 로컬 파일과 비슷한 방식으로 시스템 호출을 사용한다. [[VFS]]가 해당 경로가 NFS 마운트라는 사실을 확인하면 NFS 클라이언트로 요청을 넘긴다. 실제 디스크 블록과 파일시스템 메타데이터는 NFS 서버가 관리한다.

## 3. 사용자와 권한

NFS 환경에서는 파일 소유자를 UID와 GID로 표현하는 경우가 많다. 서로 다른 서버에서 같은 숫자가 서로 다른 사람을 뜻하면 권한이 예상과 다르게 보일 수 있다. 중앙 계정 체계, 이름 매핑과 일관된 권한 설계가 필요한 이유이다.

NFSv4 계열은 인증과 보안을 위해 Kerberos를 함께 사용할 수도 있다. 단순히 공유가 마운트되었다는 사실만으로 모든 사용자가 같은 권한을 얻는 것은 아니다.[^1]

## 4. 캐시와 파일 잠금

네트워크 파일 서비스는 성능을 위해 데이터를 캐시한다. 이때 여러 클라이언트가 같은 파일을 열면 변경 내용을 언제 다시 확인할지, 누가 쓰는 동안 다른 클라이언트가 어떻게 행동할지 정해야 한다.

NFS의 파일 잠금과 상태 관리 방식은 버전에 따라 다르다. 특히 데이터베이스나 동시에 수정되는 중요 파일은 애플리케이션 지원 여부와 마운트 옵션을 함께 확인해야 한다.

## 5. NFS와 iSCSI의 차이

| 질문 | NFS | iSCSI |
|---|---|---|
| 네트워크로 보내는 의미 | 파일 열기·읽기·쓰기 | SCSI 블록 읽기·쓰기 |
| 파일시스템 관리 | NFS 서버 | iSCSI를 연결한 호스트 |
| 클라이언트에 보이는 대상 | 공유 디렉터리 | 디스크와 같은 블록 장치 |
| 일반적인 다중 사용자 공유 | 파일 서버가 조정 | 별도 클러스터 조정 필요 |

둘 다 네트워크를 이용하지만, 네트워크에 싣는 요청의 의미가 다르다. NFS를 “파일 수준”, [[iSCSI]]를 “블록 수준”이라고 구분하는 이유이다.
