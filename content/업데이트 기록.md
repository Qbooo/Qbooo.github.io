> > > - 추가: [[ARP]], [[Default Gateway|기본 게이트웨이]]. 같은 네트워크와 다른 네트워크에서 ARP가 묻는 다음 홉 IP, 요청 브로드캐스트와 응답 유니캐스트, ARP 테이블의 갱신과 만료, 게이트웨이가 같은 서브넷에 있어야 하는 이유와 기본 경로와의 관계를 RFC 기준으로 정리.
> > > - 수정: [[Networking]], [[Networking 분류]], [[Knowledge Base/index|전체 개념 목록]], [[Encapsulation|캡슐화]], [[IP Address and Subnet|IP 주소와 서브넷]], [[Unicast Broadcast Multicast Anycast|유니캐스트·브로드캐스트·멀티캐스트·애니캐스트]]에 ARP와 기본 게이트웨이 연결을 추가.
> > > - 추가: [[IP Address and Subnet|IP 주소와 서브넷]]. 네트워크 부분과 호스트 부분, 마스크로 같은 네트워크인지 판단하는 방식, `/28`과 `/22`의 비트 계산, 클래스 기반 주소의 한계와 CIDR, 서브네팅과 슈퍼네팅의 정렬 조건, 경로 선택의 Longest Prefix Match와 기본 경로를 RFC 기준으로 정리.
> > > - 추가: [[Unicast Broadcast Multicast Anycast|유니캐스트·브로드캐스트·멀티캐스트·애니캐스트]]. 수신자의 범위로 나눈 네 가지 전달 방식, Broadcast가 L2 broadcast domain에서 멈추는 이유와 Directed Broadcast 차단, Multicast의 그룹 가입과 IGMP, Anycast의 가까운 노드 선택과 적합하지 않은 경우를 RFC와 공식 문서 기준으로 정리.
> > > - 수정: [[Networking]], [[Networking 분류]], [[Knowledge Base/index|전체 개념 목록]]에 주소와 통신 방식 문서 연결을 추가.
> > > - 추가: [[Encapsulation|캡슐화]]. Data·TCP Segment·IP Packet·Ethernet Frame의 헤더 구조, 홉마다 바뀌는 MAC 주소와 유지되는 IP 주소, 수신 호스트의 역캡슐화 순서, 인터페이스별 MAC·IP 주소와 포트의 역할, 대기 프로세스가 없는 포트의 TCP RST·ICMP Port Unreachable 응답을 RFC 기준으로 정리.
> > > - 추가: [[네트워크 장비별 처리 계층]], [[연결 거부와 시간 초과의 차이]]. 스위치·라우터·서버가 열어 보는 헤더의 범위와 홉별 변화 값, 거부와 시간 초과가 알려 주는 것과 원인 후보, NIC가 여러 개인 서버의 사례, 아래층부터 확인하는 점검 순서를 정리.
> > > - 수정: [[Networking]], [[Networking 분류]], [[Knowledge Base/index|전체 개념 목록]], [[Questions/index|질문과 해답]]에 새 문서 연결을 추가.
> > > - 추가: [[Switch|스위치]], [[Router|라우터]]. 실제 물리 장비와 내부 부품, MAC 주소 학습과 Flooding, 라우팅 테이블과 다음 홉, 링크마다 바뀌는 MAC 주소와 유지되는 IP 주소를 사진과 자체 제작 교육용 도식으로 정리.
> > > - 추가: [[Internet Routing|인터넷의 통신 구조]], [[BGP]]. 가정의 기본 경로부터 ISP 경계·코어·목적지 AS까지의 전달 과정과 AS·ASN·IP 프리픽스, 경로 광고·정책·철회·수렴, IGP와의 역할 분담을 정리.
> > > - 보완: [[Router|라우터]]에 실제 소형 라우터의 내부 회로 사진을 추가하고, [[BGP]]에 BGP 프로세스·이웃 설정·TCP 179 세션·메시지·BGP 경로표·RIB·FIB의 연결과 간단한 설정 예시를 추가.
> > > - 보완: [[Internet Routing|인터넷의 통신 구조]]에 100개 이상의 장비 노드로 현실의 연결 관계를 축소한 좌우 구조도와, 약 45개 핵심 노드의 실제 링크를 따라가는 방사형 인터넷 지도를 추가. 고객–ISP 접속 경계와 ISP Internet Edge·AS 경계를 분리하고, 접속 ISP·Transit·다른 ISP·콘텐츠 사업자가 각각 AS가 될 수 있으며 IXP는 이들이 만나는 교환 기반이라는 설명을 보완. 직접 Peering·IP Transit·온프레미스 공개 Web·Cloud 공개 진입점 경로도 그림에서 구분.
> > > - 추가: [[IXP Peering and Transit|IXP·피어링·트랜짓]], [[Backbone Network|백본 네트워크]]. IXP L2 패브릭과 Route Server, Peering과 Transit의 차이, PoP·코어 라우터·광전송망으로 구성되는 사업자 백본을 공개 자료와 자체 제작 도식으로 정리.
> > > - 심화: [[IXP Peering and Transit|IXP·피어링·트랜짓]]에 IXP의 물리 구성, Bilateral·Multilateral Peering, Route Server의 제어 평면 동작, Transit의 BGP 경로 제공과 실제 패킷 운송을 상세히 보완. 동일 구조도에서 직접 Peering과 Transit 예비 경로를 비교하고 고객–ISP 경계와 공용 인터넷 인프라 영역을 표시.
> > > - 보완: [[Internet Routing|인터넷의 통신 구조]]의 방사형 구조도에서 가입자 BNG와 데이터센터 연결 PE를 분리하고, 같은 ISP 내부 통신이 `가입자 접속 → 집선 → 코어 → 목적지 PE`를 거치는 이유와 같은 PE에서 종료될 때 더 짧아질 수 있는 조건을 설명.
> > > - 이미지 검수: 자체 제작 개념도를 정확성·가독성·재사용성 기준으로 다시 확인. IXP를 단일 라우터처럼 오해할 수 있는 초기 경로 그림은 문서에서 제외하고, 검증된 MAC 학습·홉별 프레임·테넌트 격리·스토리지 접근 방식 그림을 [[Networking]], [[File Storage|파일 스토리지]], [[Multi-tenancy|멀티테넌시]] 등 관련 문서에서 설명과 함께 재사용.
> > > - 이미지 교체: 경로 색을 고정한 방사형 그림 대신 모든 선이 실제 장비 포트끼리 연결되는 인터넷 기준 아키텍처를 제작. 접속 ISP의 BNG·집선·코어·Internet Edge, IXP의 참가자 피어링 라우터·L2 패브릭·Route Server, Transit의 Edge·Core, 콘텐츠 AS와 Cloud Provider를 분리해 [[Internet Routing|인터넷의 통신 구조]]와 [[IXP Peering and Transit|IXP·피어링·트랜짓]]에서 공동 사용.
> > > - BGP 도식 보완: [[BGP]]에 두 이웃이 TCP 179 세션에서 UPDATE를 양방향으로 교환하고, 각자 Import·Export 정책과 최적 경로 선택을 거쳐 RIB·FIB에 반영하는 구조도를 추가. 초기 경로 교환 이후에는 변화와 철회를 증분 UPDATE로 전달한다는 설명을 보완.
