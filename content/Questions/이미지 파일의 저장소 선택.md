## 질문

이미지 파일 저장소로 오브젝트 스토리지가 필요한가?

## 해답

파일을 저장하는 방식은 파일, 블록, 오브젝트로 나뉘며, 접근 방법이 다르다.

- 파일 스토리지: 파일 경로로 접근하며 NFS나 SMB 같은 표준 프로토콜로 공유한다.[^1] 웹 콘텐츠 관리와 공유 파일 저장에 흔히 쓴다.[^2]
- 오브젝트 스토리지: API 호출로 접근하며 메타데이터를 풍부하게 붙일 수 있고, 확장성과 복제에 강하다.[^1][^2]
- 블록 스토리지: 데이터베이스처럼 낮은 지연이 필요한 워크로드에 쓴다.[^1]

여러 웹 서버가 같은 업로드 파일을 읽고 써야 한다면 NFS가 자연스러운 선택이며, 같은 데이터센터의 서버 2~5대 규모에 잘 맞는다는 설명이 있다.[^3] 파일 시스템 형태를 기대하는 기존 애플리케이션에도 맞는다.[^3] 확장성이 더 필요해지면 오브젝트 스토리지가 선택지가 된다.

## 프로젝트 판단

아래 판단은 소규모 연습 프로젝트(가상의 소규모 고객, 직원 30명 안팎의 유통업체를 가정한 DR 이전 과제)에서 요구사항과 규모를 고려해 내린 것이며, 모든 환경에 맞는 정답은 아니다.

- 맥락: WAS가 2대이고 같은 센터에 있으며, 업로드 파일을 양쪽 WAS가 같이 읽어야 한다. 6주짜리 소규모 프로젝트이다.
- 판단: WAS 디스크를 따로 두지 않고 NFS 저장소 서버 한 대를 두었다. 오브젝트 스토리지(MinIO나 Zadara 오브젝트 스토리지)는 클라우드 이전 단계(4~6주차)의 선택지로 남겼다.
- 한계: NFS 서버가 새로운 단일 장애점이 된다는 점은 DR 동기화와 백업으로 완화했다.
